# cr16-2: 45-minute release-job timeout

**Candidate severity:** MEDIUM
**Disposition:** Declined at intake

The candidate argues a 30-minute `notarytool` allowance cannot fit inside the
45-minute whole-job bound if preceding work consumes more than 15 minutes. The
conditional premise has no observed trigger. Exact-head signed five-RID run
`31654609624` reached notarization 65 seconds after job start and completed the
whole macOS leg in 2m17s. Published v0.2.2 run `31239078883` reached
notarization after 46 seconds and completed in 1m32s; signed v0.2.1 run
`31225914784` has the same order of magnitude. The current workflow therefore
preserves roughly 44 minutes after reaching notarization for a 30-minute Apple
allowance, plus a large cleanup margin. A hypothetical >15-minute preceding
phase is neither measured nor tied to a named failure. Increasing every bound
would undo the observed-hang limit without repairing an evidenced defect.

This does not decline cr16-1: a random transport drop while an Apple submission
is genuinely `In Progress` is the same verified failure class that already
occurred after acceptance, and the current one-shot `info` sample demonstrably
misclassifies that valid nonterminal state.
