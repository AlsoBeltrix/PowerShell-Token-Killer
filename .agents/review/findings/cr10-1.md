# cr10-1: legacy custody receipts brick the v8 upgrade

**Severity**: CRITICAL — any v7 receiver that opened a gap, created an alert,
or retained an event can fail permanently before either listener binds.
**Status**: Verified
**Branch**: —
**Commit**: `81b9118337d13cd599aea0734b01e4ac324ecf6e`

## Evidence

`siem/PtkSiemReceiver/Storage/SqliteIngestStore.Custody.cs` verifies every
receipt's live subject after counting legacy receipts with unavailable exact
evidence. Legacy gap/alert snapshots cannot be reconstructed, and retained v7
event/quarantine sources may already be gone, so the subject check returns
false before the intended `LegacyUnverifiedReceipts` result can be used.

## Predicted observable failure

Upgrading such a database commits schema v8 and then throws
`SiemReceiverStartupException(custody_integrity_subject)`. Ingest and operator
listeners never bind; reverting also fails because the database is now newer
than v7.

## What

The migration's explicit legacy-unverified compatibility path is internally
unreachable for the exact receipt classes it was designed to carry.

## Approach

Pass the ledger version into subject verification and exempt only a v1 receipt
whose exact evidence is unavailable. It remains counted as legacy-unverified;
v1 receipts whose evidence was backfilled and every v2 receipt still receive
full subject verification. Add a faithful v7-schema upgrade guard containing
an orphaned event receipt plus gap and alert receipts.

## Guard proof

`SqliteIngestStoreTests::V7_upgrade_counts_unrecoverable_legacy_receipts_without_bricking_startup`
constructs a faithful v7 custody schema containing an orphaned retained event
receipt plus gap and alert receipts. It proves upgrade succeeds, exact live
event/quarantine evidence is backfilled, and only the unreconstructable rows
are counted. Replacing the narrow legacy exemption with `return false` makes
the test fail at startup with `custody_integrity_subject`; restoring it passes.
