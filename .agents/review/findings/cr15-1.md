# cr15-1: failed test-host startup can mask its real error on Windows

**Severity**: MEDIUM — a test-infrastructure cleanup error can replace the
actual receiver construction or startup failure across the Windows SIEM suite,
discarding the evidence CI was meant to report.
**Status**: In progress
**Branch**: —
**Commit**: pending

## Evidence

`siem/PtkSiemReceiver.Tests/SiemReceiverTestSupport.cs:276-314` builds a real
receiver application, which opens the production SQLite store before Kestrel
binds. Its failure catch disposes the application and immediately recursively
deletes the owned roots. The normal `DisposeAsync` path at lines 330-343 first
calls `SqliteConnection.ClearAllPools()` because Microsoft.Data.Sqlite retains
idle native handles; the failure path omits that same required operation.

The exact class already occurred during S8 on hosted Windows: the ordinary
test-host disposal path initially left `siem.db` locked until commit `0c35ee7`
added the pool clear. The sibling construction/start failure path uses the same
SQLite connection pooling and Windows deletion semantics but was not repaired.

## Predicted observable failure

If `ReceiverApplication.Build`, `StartAsync`, or post-bind address discovery
throws after the SQLite store opened, the catch disposes the application and
then attempts `Directory.Delete(root, recursive: true)`. On Windows, an idle
pooled SQLite native handle can keep `siem.db` open, so cleanup throws an
`IOException` naming `siem.db` and replaces the original bind, certificate,
listener, or startup exception. POSIX unlink semantics conceal the omission.

## Guard proof

Both successful and failed test-host disposal now route through one
dispose-then-clear-pools-before-delete helper. The deterministic guard injects
the start failure only after the real application and SQLite store are built,
then wraps the real `SqliteConnection.ClearAllPools` and `Directory.Delete`
implementations to assert exact cleanup order. Removing only the shared pool
clear fails on every platform with `Expected ["clear", "delete", "delete"],
Actual ["delete", "delete"]`; restoring it passes 1/1. The normal and failed
paths use the same primitive, so the original sibling-path drift cannot recur.
Full SIEM suite passes 330/330; changed-file `dotnet format
--verify-no-changes` and `git diff --check` pass.
