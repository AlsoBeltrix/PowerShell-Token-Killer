# cr2-2: Named-session calls are recorded as belonging to the default session

Severity: HIGH. Source: codereview codex (gpt-5.6-sol @ high, standard)
over `61fc838..a10ad50`, 2026-08-10. Status: CLOSED (accepted).

## Evidence

`server/PtkMcpServer/Audit/AuditCallContext.cs:759` — `CallSession()` was a
static stub returning `Name="default"`, `Generation=0`,
`BindingKind="default"` for every call, while
`AuditCallMetadata.cs` captured the requested named session into
`request.session_requested`.

## Predicted observable failure

`ptk_invoke` against `session=sample-online` journals records whose
`request.session_requested` is `sample-online` but whose canonical
`session.name` is `default` — session-scoped audit queries and the SIEM
session index attribute activity to the wrong session.

## What

`CallSession()` now derives from the validated `SessionRequested`: the
requested name (or `default` when none), `BindingKind` `dynamic` for named
sessions — inside the frozen `ptk.audit/2` enum {default, dynamic,
template}. Generation stays 0: the worker generation is unknown at the
supervisor admission boundary (recorded limitation, not an oversight).

## Guard proof

`AuditProgramStartupTests.A_named_session_invoke_is_journaled_under_its_own_session_name`
— opens a named session through the real server, invokes in it, reads the
journal after shutdown, asserts `"name":"attrib-probe"` and
`"binding_kind":"dynamic"`. Stash-revert of the fix fails exactly this
test; restored, it passes.
