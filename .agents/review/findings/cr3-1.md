# cr3-1: Exporter cannot read the active journal segment

Severity: HIGH. Source: codereview codex (gpt-5.6-sol @ high, standard)
over `1a7a71f..98a3625`, 2026-08-10. Status: FIXED IN FULL — the
visibility half landed 2026-08-10; the coordinated live-tail read landed
2026-08-11 (R3d): the exporter reads the live segment's durably
committed prefix through the journal writer's own handle
(`AuditJournal.ReadCommittedSpool`, surfaced to the export service as a
`liveJournalSource` delegate off the runtime gate), so records reach the
SIEM before rotation while the writer's load-bearing `FileShare.None`
stays untouched. A drained live tail is quiet; `export.segment_unreadable`
still fires for a segment that is unreadable and not the live journal's.
Handover at rotation shares one currency — file byte offsets on the
cursor — proved by a live→rotated continuity test (every record
delivered exactly once, no gaps). Sabotage (live read disabled) fails
both new tests; the original visibility pin still passes unchanged.

## Evidence

`AuditExportService.ReadBatch` opened its own handle and turned every
open/read failure into an empty batch, while
`FileAuditJournalSink` opens the live segment with `FileShare.None`
(verified at `server/PtkMcpServer/Audit/FileAuditJournalSink.cs:726`).

## Predicted observable failure

A configured SIEM receives nothing from the current segment — in
practice until the segment rotates or PTK restarts — while export health
still reported "healthy" and pending bytes grew.

## What (and what is deliberately deferred)

The silent half is fixed: read failures now surface as
`export.segment_unreadable` on the export health line, so an exporter
that can deliver nothing can never report healthy. **The live-tail read
itself is NOT fixed here.** The writer's `FileShare.None` is
load-bearing: `IsLockedSegment`
(`FileAuditJournalSink.cs:600`) classifies live vs closed segments by
openability, so loosening the share mode would make the writer treat its
own live segment as closed and eligible for trimming — a worse defect
than the one being fixed. The correct fix is the reviewer's first
suggestion — read through the journal's coordinated reader APIs
(`AuditLiveSpoolReader` + closed-chain reader with its durable-tail
boundary) — which is a redesign of the export read half and is
scheduled as R3d. Until then export delivers closed (rotated) segments
and reports the live-tail condition instead of hiding it.

## Guard proof

`AuditExportTests.An_unreadable_segment_is_reported_rather_than_read_as_empty`
holds a segment exactly as the writer holds its live one, asserts the
failure detail and that the status line is not "healthy", then asserts
normal delivery once released. Sabotage (restoring the silent-empty
path) fails exactly this test.

## Files changed

- `server/PtkMcpServer/Audit/Export/AuditExportService.cs`
- `server/PtkMcpServer.Tests/AuditExportTests.cs`

## Known gaps

None. The R3d coordinated live-tail read closed the deferred half; the
anchored `AuditLiveSpoolReader`/checkpoint machinery the reviewer named
was deliberately NOT restored — the mode-agnostic committed-prefix
primitive beneath it (`ReadCommittedSpool`) was sufficient and carries
none of the ack-gating design contract rule 2 forbids.
