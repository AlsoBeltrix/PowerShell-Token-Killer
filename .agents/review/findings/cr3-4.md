# cr3-4: Combined age and size retention deletes fresh records unnecessarily

Severity: MEDIUM. Source: codereview codex (gpt-5.6-sol @ high,
standard) over `1a7a71f..98a3625`, 2026-08-10. Status: CLOSED (accepted 2026-08-10, verification round 3 with the
corrected base pin `98a3625`: guard bites, no adjacent regression).

## Evidence

The age purge committed without reclaiming pages and `DatabaseBytes`
measured raw `page_count`, which still counts freed pages, so the size
loop deleted another batch before its first VACUUM.

## Predicted observable failure

When the age purge alone would make the compacted database fit the size
bound, a sweep with both bounds still deletes up to 512 newer events and
512 newer quarantine attempts that are inside the retention window.

## What

Size decisions now use live bytes — `page_count - freelist_count` times
page size — so space the age purge already freed counts as free.

## Guard proof

Rewritten: the first version chose a size bound that was never exceeded,
so it passed against the defect. It now commits 24 old records plus 6
inside the retention window and applies a bound that only the LIVE
measure satisfies after the age purge — the six in-window records must
survive. Proved to FAIL against the base file and pass at head.

sound, but against the guard: it passed at BOTH base and head, so it
never proved anything. Recorded because a guard that does not bite is
