# cr4-4: The export leg is unsafe under concurrent supervisors sharing one root

**Severity**: HIGH — durable audit records can be silently omitted from
SIEM custody, and the chain detection manufactures false proved gaps.
**Status**: In progress — REOPENED by frontier verification (see
Reviewer comments); the per-boot-position rework is the repair.
**Branch**: —
**Commit**: `7c8fa96` (first fix); repair pending

Reviewer: codex / gpt-5.6-sol / high / standard (generation pass over
`abc3292..8ab189a`, 2026-08-11). The reviewer's finding named the
cursor-past-foreign-live-segment path; coder triage widened it to the
three concurrent-exporter defects below, which share one root cause
(the export leg models exactly one supervisor per audit root) and one
fix.

## Evidence

1. **Cursor skip-ahead** (reviewer's path):
   `AuditExportService.DrainOnceAsync` — an unreadable segment breaks
   only the inner loop; the foreach continues to later segments, whose
   delivery advances the single cursor PAST the unreadable one. With a
   foreign supervisor's live segment (FileShare.None, not servable by
   this process's liveJournalSource), the cursor passes undelivered
   records; `SegmentsFrom` then skips them forever and the retention
   floor (cursor-based) no longer protects them.
2. **False gaps from interleaved boots**: `EnumerateSegments` orders by
   CreationTimeUtc, so two active boots interleave (A0, B0, A1, …). The
   chain walk crossing back into boot A at sequence N>1 records a FALSE
   proved gap `A:1-(N-1)` even though those records were delivered.
3. **Cursor/ledger write races**: every supervisor runs its own
   AuditExportService against the same `export-cursor.json` and
   `export-gaps.json`; concurrent tmp+rename writes are last-writer-wins
   and can regress the other exporter's durable position and evidence.

## Predicted observable failure

Under two concurrent PTK sessions (one shared `~/.ptk` root): records
of the older live segment never reach the SIEM after the cursor passes
them and retention deletes them without a gap (silent loss); and/or
`EXPORT_GAPS` counts rise for records that were in fact delivered
(false alarms that destroy the signal's credibility).

## What

The R3a export leg (and everything layered on it) assumed one supervisor
per audit root; the deployment reality is one supervisor per MCP
connection, many per root.

## Approach

Three coordinated changes:
1. **Single-exporter lease**: a cross-process lock file
   (`export-lease.lock`, held open FileShare.None) — only the holder
   drains; other supervisors report `export: standby` and retry
   acquisition each pump tick. Kills the cursor/ledger races.
2. **Boot-grouped traversal**: segments are traversed grouped by boot
   (groups ordered by earliest segment creation, indexes within), so the
   chain walk crosses each boot boundary exactly once — no false gaps
   from interleaving. The cursor resumes inside the same traversal
   order.
3. **Halt at the first undeliverable segment**: an unreadable segment
   (foreign live, or genuinely broken) stops the WHOLE drain rather than
   being skipped — the cursor can never pass an undelivered record, so
   the retention floor keeps protecting everything at and after it.
   Cost accepted and recorded: with two active supervisors, delivery of
   later boots lags until the blocking boot's segment rotates or its
   supervisor exits; lag is visible in health, loss is not possible.
Additionally the retention floor is extended for grouped traversal:
a closed segment is deletable only if its boot group is strictly before
the cursor's boot group in traversal order (or same boot below the
floor index) — "different boot" no longer means "already delivered or
already lost".

## Guard proof

- `AuditExportTests.A_foreign_live_segment_halts_the_drain_instead_of_being_skipped`
  — a locked older segment plus a deliverable newer one: the drain must
  deliver NOTHING past the lock and the cursor must not move beyond it.
  Reverting the halt makes this FAIL (the newer segment delivers).
- `AuditExportTests.Interleaved_boot_segments_produce_no_false_gaps` —
  segments created A0, B0, A1 with contiguous per-boot chains must
  deliver with zero EXPORT_GAPS. Reverting grouped traversal makes this
  FAIL.
- `AuditExportTests.Only_one_exporter_drains_a_shared_root_at_a_time` —
  with the lease held elsewhere, DrainOnceAsync delivers nothing and
  reports standby. Reverting the lease makes this FAIL.

## Coder dispute (if any)

None.

## Known gaps

Per-boot cursors (parallel delivery of independent boots) would remove
the halt-at-unreadable lag; deliberately not built — the single linear
cursor stays, and the lag is bounded by segment rotation.

## Reviewer comments

Reviewer: codex / gpt-5.6-sol / xhigh / frontier — escalated: T2.
codex-cli 0.147.0, batch verification with cr4-1/cr4-3 over
`8ab189a..5ddbaef`, guard_confirmed true (compile-limited variant: the
exact product-code revert removed AuditExportLease and the floor
overload so the newer test project could not compile; all three named
guards passed at head individually), capability_ok true, 2026-08-11
UTC. Verdict: **REOPENED**, correctly:

1. `AuditExportService.cs:414` — the boot-group order is recalculated
   from the earliest segment STILL PRESENT. After delivery stops in A1
   and retention removes delivered A0, an undelivered B0 can reorder
   before the cursor segment A1; SegmentsFrom then skips B0
   indefinitely — the silent custody loss recreated.
2. `FileAuditJournalSink.cs:1112` — retention recomputes the same
   mutable earliest-remaining order, so once A0 disappears it can
   classify undelivered B0 as strictly before the cursor group and
   age-delete it as though delivered.

Coder assessment: the reviewer is right, and the root cause is the
linear cursor over a MUTABLE ordering — any order keyed on remaining
files shifts when delivered segments are deleted. The repair adopts the
reviewer's original better_approach: per-boot delivery positions on the
durable cursor (and per-boot chain memory on the ledger), a stable
boot-id group order, per-boot halt instead of whole-drain halt, and a
per-boot retention floor. This also removes the accepted lag cost of
the first fix (a blocked boot no longer delays other boots).
