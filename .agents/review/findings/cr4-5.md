# cr4-5: An honest replay through the other wire encoding is quarantined as forgery

**Severity**: MEDIUM — custody keeps the record once, but replay
idempotency (a stated contract) is violated and genuine evidence is
flagged as a mismatch.
**Status**: Open
**Branch**: —
**Commit**: (pending)

Reviewer: codex / gpt-5.6-sol / high / standard (generation pass over

## Evidence

Protobuf validation sets per-record raw evidence to the WHOLE protobuf
request; JSON validation sets it to the log-record JSON. The store's
duplicate acceptance (`SqliteIngestStore.cs:207-208`) requires the raw
byte arrays to match for an event_id already present.

## Predicted observable failure

The same valid event first accepted through mTLS/protobuf and later
replayed through JSON (or vice versa) produces a `duplicate_mismatch`
quarantine row and HTTP 400; a producer can permanently mark an honest
record refused.

## What

Idempotency was keyed on transport bytes, but the identity of an audit
record is its exact JSONL body (which embeds the event hash) — the
transport envelope is not part of the evidence.

## Approach

Duplicate acceptance now compares the transport-independent
`ExactJsonBody` (identical body ⇒ identical event ⇒ idempotent accept,
whatever envelope carried it); a same-id DIFFERENT body remains the
forgery signal and quarantines exactly as before. Raw request bytes are
still stored as received for forensics.

- `siem/PtkSiemReceiver/Storage/SqliteIngestStore.cs` — body-based duplicate identity

## Guard proof

`JsonIngestTests.A_cross_encoding_replay_of_the_same_event_is_idempotent`
— delivers one event via mTLS/protobuf, replays the identical record
body via token/JSON, asserts one stored event, no quarantine, both
custody receipts present. Reverting the fix makes this FAIL
(quarantine + 400); restoring makes it PASS.
