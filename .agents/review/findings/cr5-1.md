# cr5-1: A local process can impersonate the UI standby peer and harvest its bearer token

**Severity**: HIGH — an unprivileged local process that wins the port race captures the credential for the UI's authenticated read/write surface and can reuse it later.
**Status**: Verified
**Branch**: —
**Commit**: `ee0ac2f`

Reviewer (generation): codex / gpt-5.6-sol / high / standard over
`3b8dff8..3996e6a`, verdict `findings`, capability_ok true, 2026-08-11.

## Evidence
`server/PtkMcpServer/Audit/Web/AuditWebUiService.cs:106` — the token is
created (`_token ??= LoadOrCreateToken()`) before the fixed port is bound
(line 109), and the bind-failure catch (lines 114–120) treats every
collision as another trusted supervisor without authenticating the
listener already occupying the port.

## Predicted observable failure
An untrusted local process binds port 8317 first. PTK stands by; the
owner-only `ui-token` file exists (minted by this or an earlier boot). An
operator opening the UI sends the bearer token (header or query) to the
squatter, which can then release the port, wait for PTK to bind, and
replay the stolen token to read audit records or rewrite export settings.

## What
The trust model treats port ownership as proof of being a peer
supervisor, and the credential outlives any particular listener, so a
harvested token stays valid indefinitely. Verified at intake: token
minting precedes the bind, and the catch block is condition-free.

## Approach
The credential is bound to the listener instead of the root: the
service binds FIRST, then mints a fresh token for that bind
(`MintAndPublishToken`, no reuse of a retained file), publishes it
atomically only while owning the listener, and deletes it in
`StopAsync` before releasing the port. A bind-failed standby never
touches the file. Consequences: nothing is ever published toward a port
a squatter could own; a token harvested from a stale file or a spoofed
page is worthless against every future real listener (rotation); and an
unpublishable token releases the port and falls back to standby retry
rather than serving a UI whose credential the operator cannot read.

## Residual risk (stated, accepted)
A crash leaves a stale token file (no delete ran); its token is dead —
rotation invalidates it at the next bind, so a squatter that harvests
it gains nothing but the phishing window itself. Spoofing (a fake page
on a squatted port shown to an operator who types the URL by hand) is
inherent to unauthenticated localhost HTTP and out of scope; the class
doc states it.

## Coder dispute (if any)
None. Intake note on scope: an unauthenticated localhost HTTP page can
always be *spoofed* by a squatter (fake UI content); what this fix must
close is credential capture-and-reuse — the published token must never
be valid for any listener other than the one that minted it.
