## Evidence
`server/PtkMcpServer/Audit/Web/AuditAlertWebhookService.cs:129` — the
lineage condition fires only when the live count is positive and
`_notifiedLineageFailures == 0`; after acknowledgment line 211 sets the
notified value positive, and no code path ever resets it.

## Predicted observable failure
After the first acknowledged lineage failure: growth from one to two
consecutive failures is ignored (contradicting the growth contract every
other counter honors), and recovery to zero followed by a fresh failure
episode is also ignored — for the remaining process lifetime.

## What
Unlike the monotonic counters (compared with `>`), lineage is live
state compared with `== 0` against a baseline that never resets, so the
condition can fire at most once per process.

## Approach
The condition now compares growth like every other counter
(`LineagePublishFailures > _notifiedLineageFailures`), and a live count
of zero re-arms the edge by resetting the acknowledged baseline on any
pass that observes it — recovery-then-new-episode pages again, growth
within an episode pages again, unchanged state stays silent.
