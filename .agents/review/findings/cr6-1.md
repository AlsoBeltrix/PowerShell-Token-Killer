## Evidence
`siem/PtkSiemReceiver.Tests/ProducerConformanceTests.cs:124` — the
search walks from `AppContext.BaseDirectory` to the filesystem root and
accepts the first matching
`server/PtkMcpServer.Tests/SiemConformance/<name>`, never identifying
or stopping at the current repository root.

## Predicted observable failure
A checkout missing its goldens under an enclosing workspace that
contains the same path passes conformance against the stale external
corpus instead of failing closed.

## What
The fail-closed gate has a hole above the repo root: "found somewhere
up the tree" is not "found in THIS checkout".

## Approach
The locator resolves the checkout boundary first — the first ancestor
carrying a `.git` entry (directory or worktree file) — and looks for
the corpus only beneath it; absent there, it throws the fail-closed
error naming the exact expected path, without ever ascending past the
boundary. The walk is parameterized by start directory for the guard.
