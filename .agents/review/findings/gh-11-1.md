# gh-11-1: Public transport death boundary was undocumented

**Severity**: MEDIUM — a dead public stdio server can leave a client tool entry
present even though PTK cannot reattach a replacement process to the old pipes.
**Status**: Accepted; pending integration
**Branch**: `docs/issue-11-transport-boundary`
**Commits**: `37f6182`, `924cc2e`
**Source**: GitHub issue #11

## Evidence

Issue #11 records a Codex session whose old direct PTK server exited and whose
tool calls then failed with `Transport closed`. The current worker-supervisor
topology can recover a contained session worker behind a live public connection,
but no public process can reopen client-owned stdio after that process exits.

Real Codex 0.146.0 checks against installed `0.2.0-dev.g12e1ff5` proved both
boundaries. Killing path-verified worker PID 17048 under supervisor PID 4772
kept the same MCP connection usable, exposed ready replacement PID 17304 with
`warm_state_lost=true`, and allowed a new invocation. Killing path-verified
public supervisor PID 8124 made the next same-client call fail immediately with
`Transport closed`; fresh Codex supervisor PID 25360 invoked successfully and
remained ready. All diagnostic processes were gone after their clients exited.

## Predicted observable failure

A caller can mistake session-worker recovery for a promise that PTK will also
resurrect its public MCP process, repeatedly call a dead client tool entry, and
wait for recovery that only a fresh harness session can provide.

## What

Document the asymmetric boundary: confirmed-contained worker loss is recovered
per session without closing public MCP, while public `PtkMcpServer` death closes
that client connection irreversibly and requires a fresh harness session.

## Guard proof

This documentation-only slice adds no executable guard and has no revert proof.
The real Codex checks above directly validate the documented current boundaries.

## Known gaps

PTK does not promise universal client-side MCP restart inside an already-running
harness session. The original older-build exit cause remains unknown; closure
does not rewrite that observation.
