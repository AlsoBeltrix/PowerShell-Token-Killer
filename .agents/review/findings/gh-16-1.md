# gh-16-1: Completed output has no retained discovery index

**Severity**: HIGH — a successful long or paid invocation can become permanently unreachable when its MCP response channel closes.
**Status**: Accepted; pending integration
**Branch**: `fix/issue-16-output-discovery`
**Commit**: `6d5dcd2`
**Source**: GitHub issue #16

## Evidence

Issue #16 records a `ptk_invoke` whose 900-second execution budget outlived the
caller's 300-second MCP deadline. The external child completed successfully, the
same warm named session returned idle with exit code 0, and `OutputStore` sealed
the immutable artifact, but response delivery failed after the channel closed.
`OutputStore` retained only a private session-generation alias and exposed
artifacts only through the random handle carried by that lost response.

## Predicted observable failure

Discarding a completed invocation response leaves no public operation able to
locate the already-sealed artifact by named session. The only recovery is to
rerun work whose effects, cost, or exact result may not be safely reproducible.

## Approach

Add an internal, bounded retained-discovery model before changing the public
tool contract. Every reservation now stores a validated public session label
separately from the existing private quota/generation alias. `OutputStore.List`
returns only sealed readable entries, newest first by monotonic sequence, with a
hard item bound and optional public-session filter. Pending captures and
retention tombstones remain undiscoverable. The named-session supervisor threads
the validated public name into capture without changing worker protocol, quota,
retention, invocation, or existing handle semantics.

## Known gaps

This slice is internal and does not yet make discovery callable through
`ptk_output`; that is the separately reviewed Slice 2 in
`.agents/plans/issue-16-output-discovery.md`. Discovery remains connection-local,
retention-bounded, and unavailable after server restart by design. Public listing
will intentionally make retained bearer handles enumerable within the same MCP
connection; Slice 2 must document and audit that capability change.
