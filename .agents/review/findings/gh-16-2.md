# gh-16-2: Retained output is not discoverable through the public tool

**Severity**: HIGH — a successful paid or effectful invocation can remain unreachable after its MCP response channel closes.
**Status**: In progress; pending review
**Branch**: `fix/issue-16-output-list-tool`
**Commit**: `3833003`
**Source**: GitHub issue #16

## Evidence

Slice 1 retained sealed artifacts by public named session, but `ptk_output` still required a handle in its generated schema and exposed only `read`, `search`, and `status`. A caller that lost the original `ptk_invoke` response therefore had no public operation that could recover the sealed handle without rerunning the invocation.

## Predicted observable failure

After a caller disconnects before receiving a completed invocation response, a same-connection client cannot locate and read that invocation's retained output by named session. Rerunning the operation can duplicate effects or cost.

## What

Expose fixed-maximum retained discovery through `ptk_output(action="list", session="<name>")`, while keeping list non-executing, connection-local, retention-bounded, and strict at the audit and direct-tool boundaries.

## Approach

Make `handle` optional only at the public schema boundary and require it at runtime for the existing actions. Add `list` with an optional bounded session filter and format at most ten newest retained snapshots as line-oriented records whose handles pass directly to `read`. Audit metadata admits list without a handle protector, records only the requested session, rejects every inapplicable argument, and leaves the strict audit event schema unchanged. Update the frozen public contract, registered handshake assertions, raw-usage guidance, and recovery documentation.

## Known gaps

Discovery is intentionally limited to the current MCP connection, current retention window, and ten newest matching artifacts. It does not survive server restart and does not paginate. The local SIEM suite could not exercise 21 symbolic-link fixture cases because this ordinary Windows token lacks symbolic-link privilege; that machine limitation is already recorded in `.agents/machines.md`, and hosted CI remains the cross-platform gate.
