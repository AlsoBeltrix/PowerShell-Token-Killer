# o53-3: structuredContent hides every completed call's output in clients that prefer it

**Severity**: HIGH — in Claude Code, ptk's primary harness, every `ptk_invoke` response rendered as the three-field verdict JSON instead of the compressed output; the product's entire purpose (and even the recovery-handle line) was invisible to the consuming agent.
**Status**: Verified — fixed `a5e2558` and confirmed live in Claude Code after the owner's reinstall + reconnect (2026-08-07): the probe that previously returned only the verdict JSON shows full output and its recovery handle, and a refusal renders as a flagged error carrying its complete reason
**Branch**: —
**Commit**: (see git history 2026-08-07)

## Evidence

Field report by the owner (an agent on a freshly updated install: "returns output only via handles now"), then reproduced firsthand in this repo's own Claude Code session against the reinstalled head build: `ptk_invoke` of `'alpha-line-1'; 'beta-line-2'; 'gamma-line-3'` returned to the model **only** `{"disposition":"completed","executed":true,"safe_to_resubmit":false}` — no output lines, no status lines, no recovery handles. The server-side text was intact the whole time (`Content[0].text` unchanged byte-for-byte, proven by the handshake gates); the client replaces text content with `structuredContent` whenever it is present.

## Predicted observable failure

Observed, not predicted: any agent in such a client loses all inline output on every call, cannot see recovery handles (they live in the text), and the token-compression product delivers zero tokens of output.

## What

The opr-53 repair attached PTK's verdict as `structuredContent` to **every** session-tool response. The MCP spec has clients treat structured content as the primary result when present; Claude Code renders it *instead of* the text blocks. A verdict channel that costs the output channel is the wrong trade on the 99% path.

## Approach

Owner delegated the design call to agent judgment (2026-08-07, "This is consumed by agents. You're an agent. What do YOU need?" — under the recorded agent-experience-leads practice). The agent's needs, in order: the output as bare text on the ordinary path; an unforgeable verdict exactly when PTK has something to say; the full text still reachable when that verdict appears. Implementation:

- **Completed responses carry no `structuredContent` at all** — bare text, byte-for-byte, exactly the pre-opr-53 wire shape. Absence is itself the completed verdict: worker output can no more add a structured field than remove one, so a script printing a fake refusal cannot un-complete a call, and a genuine refusal's fields cannot be forged.
- **Non-completed responses** (`not_started`, `outcome_unknown`, `failed`) keep the structured verdict and additionally carry a `text` field mirroring the full response text, so structured-preferring clients still see the refusal reason and any recovery handle. The mirror is worker-tainted by definition; the verdict fields are the trustworthy half.
- **`SupervisorCallFilter` gates its text matcher by tool identity** (`ptk_output` only), never by response shape — completed session-tool responses no longer have a structured marker to recognize them by, and matching their text would let worker output forge `isError` back into the channel opr-53 removed it from.

## Files changed

- `server/PtkMcpServer/Sessions/ToolOutcome.cs` — completed → bare text; non-completed → verdict + `text` mirror; remarks updated.
- `server/PtkMcpServer/SupervisorCallFilter.cs` — matcher gated on `toolName == "ptk_output"`.
- `server/PtkMcpServer.Tests/ToolOutcomeTests.cs`, `SupervisorCallFilterTests.cs` — expectations reshaped; new guards.

## Guard proof

- Sabotage A (restore the old always-structured completed shape): exactly 4 ToolOutcome tests fail (forgery test now asserting structured absence, the completed theory rows); restored → green.
- Sabotage B (remove the filter's name gate): exactly the 4 rows of `A_session_tools_text_is_never_matched` fail (a session tool's text leading with PTK's own refusal marker must never set `isError`); restored → green.
- Full battery + handshake per the verification record in `.agents/state.md`.
- Final rendering confirmation requires one live MCP reconnect in Claude Code (owner action): a `ptk_invoke` must show its output text again.

## Known gaps

Client rule is documented in code remarks: absence of `structuredContent` = completed. A client that requires the field's presence to trust a completed verdict has no marker to read; it inherits exactly the pre-opr-53 posture on the completed path, which the owner's harness population (text-preferring and structured-preferring both) handles correctly.
