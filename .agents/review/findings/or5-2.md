# or5-2: a closed or failed-open alias name is burned for the guardian's lifetime

**Severity**: HIGH — after close or any failed open, the alias name can
never be reopened; the refusal message is factually false; a failed open
also strands the alias in recovery_unknown with no way back.
**Status**: Open
**Branch**: `feature/mcp-resilience-r1` (worktree `.claude/worktrees/mcp-resilience-r1`)
**Commit**: —

## Evidence
`GuardianHostSupervisor.DispatchSessionOpenAsync` refuses open whenever
`TryGetJobListTarget` succeeds (any declared alias, including Cold) and
calls `DeclareDynamicAlias` *before* dispatch with no compensating action
on failure; `FrozenDefaultSessionState` has no removal path; a failed open
marks the alias `recovery_unknown`, which still blocks reopen.

## Predicted observable failure
open build → close build → open build returns "already exists" (false and
unrecoverable). An open that fails inside the host returns outcome_unknown
and the alias is stuck in recovery_unknown — reopen refused forever.

## What
Make declaration reversible and reopen legal: gate reopen on observed
state rather than mere declaration (a Cold alias may be reopened);
compensate a terminal open failure by undeclaring the alias and releasing
its generation watermark; or declare only after the ready lifecycle lands,
holding a short-lived reservation so the capability grant still validates.

## Guard proof
New tests: open→close→open succeeds on a fresh generation; a failed open
leaves no declaration (reopen succeeds).

Empty.
