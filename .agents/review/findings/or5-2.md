# or5-2: a closed or failed-open alias name is burned for the guardian's lifetime

**Severity**: HIGH — after close or any failed open, the alias name can
never be reopened; the refusal message is factually false; a failed open
also strands the alias in recovery_unknown with no way back.
**Status**: Verified
**Branch**: `feature/mcp-resilience-r1` (worktree `.claude/worktrees/mcp-resilience-r1`)
**Commit**: `9283ac9`; reviewed range `9bf51ff..9283ac9`; repair `08d28d5`

## Evidence
`GuardianHostSupervisor.DispatchSessionOpenAsync` refused open whenever
`TryGetJobListTarget` succeeded (any declared alias, including Cold) and
called `DeclareDynamicAlias` before dispatch with no compensating action
on failure; `FrozenDefaultSessionState` had no removal path;
`WorkerPrivateHostRuntime.OpenWorkerAsync` refused every existing alias.

## Predicted observable failure
open build → close build → open build returned "already exists" (false and
unrecoverable); an open that failed inside the host returned
outcome_unknown and the alias was stuck — reopen refused forever. A reopen
with a different `allowColdBackground` diverged the binding digest and
escalated to whole-host loss.

## What
Reopen is legal and exact: the guardian gates on observed state
(declared + Cold may reopen), reuses the declared binding verbatim (never
recomputed — no digest divergence), refuses a mismatched
`allowColdBackground` in-band, and declares only entirely new aliases; a
terminally failed open marks only the dynamic alias's desired state Cold
(no undeclare — redeclaration deterministically throws, so removal was
dropped per the plan review). The host refuses only a live slot
(`SessionBusy`) or faulted alias (`SessionFaulted`) and reopens slotless
aliases through the existing entry (its binding and watermark).
