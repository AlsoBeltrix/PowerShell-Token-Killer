# or5-3: an explicitly closed session is silently resurrected by host recovery

**Severity**: MEDIUM — recovery recreates a worker (process, runspace,
generation) for a session the operator explicitly closed, contradicting
the plan's "a closed alias is not speculatively opened".
**Status**: Verified
**Branch**: `feature/mcp-resilience-r1` (worktree `.claude/worktrees/mcp-resilience-r1`)
**Commit**: `47d9800`; reviewed range `4ea641a..47d9800`; repair `c4c1253`

## Evidence
`FrozenDefaultSessionState.AliasState.Binding` was immutable and always
declared `DesiredSessionState.Ready`; close only mutated observed state;
the recovery manifest was built from those bindings, and
`WorkerPrivateHostRuntime.ValidateInitialization` creates a slot for every
Ready binding.

## Predicted observable failure
`ptk_session close name=scratch` succeeds; the host later dies and
recovery launches a fresh worker for `scratch` because its binding still
says Ready — resurrecting a closed session.

## What
Desired state is now mutable per-alias intent
(`AliasState.DesiredState`, starts Ready); `ObserveSessionOperationResult`
sets Cold on `SessionCloseResult` and Ready on open/reset/restart results;
`Create` emits each binding with the mutable desired state, reusing the
original binding instance (and its original digest) whenever the desired
state is unchanged. The immutable binding keeps the alias's stable
identity; capability validation is unaffected; the host already creates
slots only for Ready bindings.

## Files changed
`FrozenDefaultSessionState.cs` (mutable desired state, manifest
projection, snapshot projection), `FrozenDefaultSessionStateTests.cs`.

## Guard proof
- `FrozenDefaultSessionStateTests.Closed_dynamic_alias_is_declared_cold_in_the_next_manifest_and_reopen_flips_it_back`:
  close flips the manifest declaration to Cold with the original digest
  (default stays Ready); reopen flips it back to Ready. Reverting the
  projection to the frozen desired state turns the Cold assertion red
  (verified).
