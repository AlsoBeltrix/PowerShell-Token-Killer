# rr-10: Zero-length audit quota control under concurrent start

**Severity:** HIGH — a shared spool root can become permanently unusable.
**Status:** FIXED on `master` (the commit carrying this record); reviewer
verdict pending (codex transport failure, see the dispatch record in
`.agents/plans/release-0.3.0-rc.6.md`).
**Scope:** `server/PtkMcpServer/Audit/AuditSpoolQuotaLease.cs` and
`server/PtkMcpServer.Tests/AuditSpoolQuotaLeaseTests.cs`.

CI run `40377656597` (ubuntu, head `812bc46c`, 2026-10-26) failed
`FileAuditJournalSinkTests.Concurrent_factories_converge_on_one_host_identity_without_temporary_files`
with `IOException: The audit spool quota control is invalid`, thrown by
`AuditSpoolQuotaLease.VerifyRetainedControl` inside `CreateControlAndAcquire`.
The same test passed 25 of 25 local runs on macOS and on the next CI run, so
the window is small; it is not imaginary.

`EnsureControlFile` created `.ptk-audit-quota.lock` in place with
`FileMode.CreateNew`/`FileShare.None` and wrote the one-byte marker only
afterwards. On Unix, .NET emulates `FileShare` with `flock`, taken after
`open(2)`. A concurrent acquirer can therefore open the still-empty control
and win the exclusive lock between the creator's open and its lock; it then
verifies a zero-length control and fails closed. The creator's own open
fails with a sharing violation, is swallowed by the "a concurrent writer
published it" catch, and nobody ever writes the marker: the zero-byte
control stays, and `EnsureControlFile` returns early on every later start
because the entry exists. Impact: two supervisors initializing one audit root
at the same time can leave that root failing closed until an operator removes
the control by hand.

## Repair and proof

The marker is now complete and durably flushed in an exclusive temporary file
(`.ptk-audit-quota.lock.<guid>.tmp`) and published with
`SecureAuditStorage.PublishAtomically`, the no-replace primitive the host
identity already uses (`MoveFileEx` without replace on Windows, hard link
plus unlink on POSIX). A creator that loses the publish race discards its
copy and acquires the winner's control, which the existing exclusive
acquisition still validates byte for byte. Any other failure removes the
temporary file and propagates.

Guards: `Writer_creation_never_exposes_a_partial_control` hooks the instant
before publication and asserts the control name does not exist while the
pending file already carries the full marker, then that no temporary file
survives; `Concurrent_writer_creations_converge_on_one_control_without_temporary_files`
holds eight creators at that instant with a barrier and releases them to
publish at once. Red evidence is the CI failure itself: the old window lies
inside .NET's open-to-lock sequence and cannot be forced from a test, so the
guards encode the invariant the fix establishes rather than replaying the
race. Focused lease and journal-sink tests: 65/65 on this host. Full server
suite: 1,398/1,398 (the two new guards included) on a clean rerun; a
first run under host load (eleven minutes instead of under three) failed
two unrelated timing tests once, `UnixWorkerContainmentRegistryTests.
A_transient_identity_failure_does_not_release_a_live_escape` and
`InvokeToolTests.Timeout_response_does_not_wait_for_the_replacement_runspace`,
neither with a recorded flake history. `git diff --check` clean.
